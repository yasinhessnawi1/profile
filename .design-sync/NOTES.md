# design-sync notes: Signal (profile site)

Target: claude.ai/design project "Signal Design System (Code)" (`projectId` in config.json). The older "Signal Design System" project is the original design handoff; it is not synced from here.

## How this repo is wired

- The site is a Next.js app with no build artifact for its components. `.design-sync/pkg/` is a stand-in package:
  - `package.json` and the `index.ts` barrel over `src/components/signal/*` are committed.
  - `types/` (tsc declarations) and `signal.css` (Tailwind output) are generated by `node .design-sync/build.mjs`, which is `cfg.buildCmd`. Always run it before `package-build.mjs` or `resync.mjs`.
- Do not point the converter at the repo root as the package. Its .d.ts scan walks every `*.d.ts` under the package dir, including the gitignored `Signal Design System/` export from the original handoff. That export has a stale API (`tw`, `iconOnly`, `ProjectLink`…), and it silently became the component contracts on the first attempt.
- `.design-sync/tsconfig.json` (`cfg.tsconfig`, used for bundling and previews only) maps `@/*` to `src/*`. It also maps `next/image` to `.design-sync/shims/next-image.tsx`, a plain `<img>` with the same `fill` layout. The real next/image needs the Next server (`/_next/image`), so ProjectCard covers would never load outside the site.
- The root `tsconfig.json` excludes `.design-sync`, `.ds-sync` and `ds-bundle`. Previews import from `signal-ds`, which only resolves inside the converter, so without the exclude `next build` type-checking would fail.
- Install with `npm ci`, from package-lock. The pnpm-era node_modules that were on disk before 2026-10-22 held older framer-motion, tailwind-merge, cva and tailwindcss than the lockfile, which is what Vercel ships.
- CSS: `.design-sync/ds.css` imports the Google Fonts and `src/app/globals.css`, and defines `--font-display/sans/mono`. On the site, next/font sets those on `<body>`. `.design-sync/tailwind.config.ts` extends the site config: it adds the previews as content and safelists the token utility families (the vocabulary listed in conventions.md).
- `cfg.dtsPropsFor` hand-writes props for Icon, Input, SocialLink, ProjectCard and Dock. The extractor can't flatten `IconName` (`keyof typeof ICONS`, 29 members, over its length cap). `build.mjs` exits 1 if `icon.tsx` gains or loses a glyph and prints the new union to paste in.
- `.design-sync/docs/<Name>.md` are category-only stubs (Core/Forms/Brand/Motion) that set the groups. Their bodies are empty on purpose, so `.prompt.md` is synthesized from props plus the preview examples.

## Previews

- The card page body is white (`background:#fff`) and Signal is dark-first, so every export wraps its content in a `bg-bg … font-sans text-fg` div. That wrapper is written inline: preview source becomes the `.prompt.md` examples, so no local helper components.
- Images point at the live site (`https://yasinhessnawi.online/*.png|.JPG|.svg`) and `https://safemediai.com/favicon.ico`.
- Not previewed: ResumeCard's expanded state (needs a click), hover states, and Input `disabled` (the component has no disabled styling, so the cell looked identical to the default and was dropped).
- `cfg.overrides`: Dock and Tag use `cardMode: column` (`[GRID_OVERFLOW]`).

## Known render warns

- BlurFade: the `package-capture.mjs` sheets show both cells as an empty dark box. The capture pins `Date` (`clock.setFixedTime`) and framer-motion's entrance stalls at opacity 0. With a real clock both cells render fully (checked by screenshot on 2026-10-22). Grades are recorded with that note. It is not a component bug.
- validate `tokens: 1 missing`: these are Tailwind-internal `--tw-*` variables that have fallbacks. Harmless.

## Re-sync risks

- If an icon is added to `icon.tsx`, `build.mjs` fails until the five `dtsPropsFor` unions are updated.
- New props on Icon, Input, SocialLink, ProjectCard or Dock won't appear in their `.d.ts` until `dtsPropsFor` is edited by hand. The other nine components are extracted automatically.
- A new component in `src/components/signal/` needs a line in `pkg/index.ts`, a category stub in `docs/` and a preview.
- Preview images depend on the live site's public paths staying put. If they move, ProjectCard falls back to its placeholder and Avatar to its initials.
- Fonts load from Google Fonts at runtime (`[FONT_REMOTE]`). Nothing is self-hosted.
- The next/image shim ignores `sizes`/`quality`/`priority` semantics; layout only (`fill`).

## Re-sync recipe

1. Run `npm ci` (Node 22).
2. Re-stage the converter: `cp -r <skill>/{package-*.mjs,resync.mjs,lib,storybook} .ds-sync/`, then in `.ds-sync/` run `npm i esbuild ts-morph @types/react playwright@1.64.0`. Playwright 1.64.0 is pinned because it matches the cached chromium build 1248 in `~/Library/Caches/ms-playwright`.
3. Run `node .design-sync/build.mjs`.
4. Fetch the project's `_ds_sync.json` into `.design-sync/.cache/remote-sync.json`.
5. Run `node .ds-sync/resync.mjs --config .design-sync/config.json --node-modules ./node_modules --out ./ds-bundle --remote .design-sync/.cache/remote-sync.json`.
